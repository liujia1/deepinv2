# 15.0 本章导读：架构即先验——去噪器长什么样，决定了它能学到什么

> “前14章我们一直在说扩散模型要‘学一个网络’，但奇怪的是——这个网络到底长什么样，我们从来没认真看过。” 这一章，我们就来把它摊开在桌面上。

前14章我们干了一件漂亮的事：把扩散模型“学什么”和“怎么学”讲清楚了。第5–6章的采样路径告诉我们，要去学**得分函数**（score function，白话：描述“当前这团噪声往哪个方向走最像真实数据”的梯度场）$s(x_t)=\nabla\log p_t(x_t)$；第8–11章的变分路径告诉我们，去学**噪声预测**（noise prediction，白话：网络猜出“加进来的那团噪声长什么样”）参数 $\epsilon_\theta$；第12章证明 Score ≡ ELBO，两条路殊途同归；第14章的 Flow Matching 更干脆，直接学**向量场**（velocity field，白话：把噪声“搬运”到数据的那条速度流线）$v_t(x_t)$。

可是你有没有发现一个漏洞？我们说“用一个网络去逼近这些目标”，但**这个网络到底长什么样**，前14章一直当成黑盒子。本章要补上这关键的一环：支撑扩散模型（也包括 Flow Matching）的那个“去噪器”本身，它的结构是怎么设计的，又为什么这么设计。

这件事可不是“实现细节”那么简单。去噪器 $D_\theta(x_t,t)$（白话：吃一张带噪图 $x_t$ 和时间步 $t$、吐出预测的网络）的架构选择，直接决定了它所学到的**隐式先验**（implicit prior，白话：网络在训练数据里“潜移默化记住”的关于图像的默认假设，比如“图像通常平滑”“物体有边界”）$p_\theta(x)$ 的表达能力。回忆第5章5.3节的 Tweedie 等式：去噪器和得分函数是等价的——去噪器烂，得分估计就烂。一个容量不足或设计别扭的去噪器，训练目标再漂亮也救不回来。

**一句话立住本章的flag：架构即先验（architecture is prior）。** 去噪器不只是一个函数逼近器，它更是隐式先验的“容器”。UNet 的多尺度特征提取，编码的是“图像有从细到粗的多层结构”这个假设；DiT 的全局自注意力，编码的是“图像任意两个位置都可能有关联”这个假设。选哪种架构，本质上是在选“你事先替模型相信了什么”。

本章走一条“理解现状 → 补关键机制 → 架构革命 → 实践选择 → 工程落地”的路，五站依次是：

- **去噪器的经典架构（15.1）**：CNN 靠卷积的局部视野和参数共享，天生适合图像；DnCNN 证明“深度 CNN 能去噪”。UNet 在 CNN 上加了编码器-解码器（encoder-decoder，白话：先层层压缩抽特征、再层层恢复出图像）和**跳跃连接**（skip connection，白话：把压缩时提取的细节“抄近路”直接送给恢复阶段），成了扩散模型前十年的标准去噪器。
- **时间步嵌入（15.2）**：扩散去噪器跟普通去噪器最大的不同是它需要“看时间”——噪声有多少，完全由时间步 $t$ 决定。我们用正弦位置编码把标量 $t$ 变成高维向量，再用 adaLN-Zero 等方式“注入”网络。
- **从 ViT 到 DiT（15.3）**：Vision Transformer 把图像切成小块当“词”处理，证明 Transformer 也能做图像任务。DiT 把这套思路搬进扩散去噪器，用 Transformer 换掉 CNN。
- **UNet vs DiT（15.4）**：这俩是两种哲学——CNN 的归纳偏置（inductive bias，白话：架构自带的人为假设）vs Transformer 的数据驱动。“归纳偏置是小数据的朋友、大数据的敌人”。
- **训练最佳实践（15.5）**：好架构只是起点，优化器、学习率、初始化、过参数化这些“最后一英里”才决定它真能跑出好结果。

```
经典架构(15.1) → 时间步嵌入(15.2) → ViT→DiT(15.3) → 架构选择(15.4) → 训练实践(15.5)
```

读完本章，希望你能带走一个比“会用哪个网络”更深的认识：**架构不是理论之外的实现细节，它是隐式先验的具体形状——每一次选架构，都是在做一次先验设计。** 下一章（第16章），我们就要把这些网络真正用到 CT、MRI 这类逆问题上去。

**本章目标**（读完后你应该能）：
- 说清为什么扩散去噪器需要编码器-解码器 + 跳跃连接，而不是普通 CNN；
- 解释时间步嵌入是“怎么让同一个网络在不同噪声水平下变策略”的；
- 对比 UNet 与 DiT 的设计哲学，并知道什么场景该选谁；
- 跑通一个最小 UNet/DiT 的前向 shape 变化，确认“输入同尺寸、输出同尺寸”真的成立。
